## 1. 总览

### 1.1 P2 定位

P2 不是"让 AI 代写论文"，而是：

> 把 P1 的结构化证据，转成符合目标期刊要求的 SCI 稿件。

核心输入是 P1 的接口文件 + P4-a 的期刊方向 + 用户定制需求。
核心输出是给 P3 的稿件包和给 P4-b 的稿件质量信息。

### 1.2 P2 在整体流程中的位置

```text
P4-a 题材初判
  ↓ 期刊方向、写作约束
P1 生信分析
  ↓ p1_to_p2_evidence.yaml + handoff + 图表
P2 SCI 写作
  ↓ 稿件包
P3 排版
  ↓ 投稿包
P4-b 成稿复审
  ↓ 推荐期刊
```

### 1.3 P2 核心原则

- 用户管方向和取舍，agent 管执行和记录。
- 叙事按需定制，不替用户编故事。
- 排版是重点，叙事是骨架，等需求。
- 所有数字锚定 P1 台账。
- 所有引用来自 BibTeX 库，不编造。
- 主张强度 ≤ 证据上限。
- 每条规则必须能构造 FAIL 用例，否则不立。

### 1.4 P2 完整流程（初稿）

```text
读 P1 接口文件
  ↓
读 P4-a 期刊方向包
  ↓
读用户定制需求
  ↓
判断输出级别（L0/L1/L2）
  ↓
按级别执行：
  ├── L0：一句话卖点 + 链条顺序 + 章节骨架标题
  ├── L1：各节要点 + 图序与图注占位 + 主张-锚对应
  └── L2：走 WP-1~9 九节点全量生成
  ↓
一致性检查（NC-1~7 + 数字 + 术语 + 逻辑）
  ↓
多模型复审
  ↓
修订
  ↓
生成 P2 接口文件
  ↓
交给 P3 和 P4-b
```

## 2. P2 输入接口

### 2.1 输入来源

| 来源 | 输入 | 用途 |
|---|---|---|
| P1 | `p1_to_p2_evidence.yaml` | 主张、证据、图表、方法 |
| P1 | `handoff.md` | 每步做了什么、能不能用 |
| P1 | `figure_index.yaml` | 可用图表 |
| P1 | `result_index.yaml` | 可用结果 |
| P4-a | 期刊方向包 | 叙事、结构、字数、摘要形式 |
| 用户 | 定制需求清单 8 项 | 个性化 |
| 用户 | 已有模板、排版参数 | 约束 P3，也约束 P2 |

### 2.2 输入检查

agent 在开始写作前，必须检查：

| 检查项 | 失败动作 |
|---|---|
| P1 接口文件存在 | 报用户，要求先跑 P1 |
| 至少 1 条 evidence | 报用户，证据不足 |
| 至少 1 张图 | 报用户，图件不足 |
| P4-a 期刊方向包存在 | 报用户，或退化为 L0 |
| 用户定制需求清单 | 未填则退化为 L0/L1 |

### 2.3 P2 配置

文件：`02_writing/p2_config.yaml`

```yaml
project_id: project_001
target_journal: null
target_publisher: null
output_level: L0          # L0 / L1 / L2
story_type: null          # data-driven / hypothesis-led / methodological
evidence_boundary: null   # 相关 / 提示 / 候选 / 已证实
figure_limit: null
audience: null            # 临床 / 生信 / 交叉
language: en
spelling: american        # american / british
structure: S1             # S1 / S2-a / S2-b / S2-c
customization: null       # 8 项定制需求清单
```

## 3. L0/L1/L2 三级输出

### 3.1 三级定义

| 级别 | 触发条件 | 交付到什么程度 | 允许写多深 |
|---|---|---|---|
| **L0 方向** | 用户未给需求（默认） | 一句话卖点 + 链条顺序 + 章节骨架标题 | 只到标题/一段话，**不写正文** |
| **L1 骨架** | 给了研究问题/终点/期刊 | 各节要点 + 图序与图注占位 + 主张-锚对应 | 每节要点 3–5 条，不铺陈 |
| **L2 定制成稿** | 给了《定制需求清单》全项 | 按期刊模板的成稿（走 WP-1~9） | 全量，受 NC-1~7 约束 |

### 3.2 默认动作

> 缺需求时出 L0/L1，并在交付物顶部标明级别与"待定制项"。**不得**在没有需求的情况下自行判定期刊定位、故事线风格或主张强度。

### 3.3 输出标记

每个交付物顶部标：

```markdown
> 输出级别：L1
> 待定制项：目标期刊、故事线偏好、证据边界、图数上限
> 下一步：用户填完 8 项定制需求后升 L2
```

## 4. 定制需求清单 8 项

### 4.1 清单

问了才升 L2。

1. **研究问题/卖点**：一句话主张是什么（预后模型？机制提示？方法学贡献？）
2. **目标期刊与栏目**：决定字数/图数/参考文献上限与版式
3. **故事线偏好**：发现型（data-driven）/ 验证型（hypothesis-led）/ 方法学型
4. **证据边界**：允许写到什么强度（相关 / 提示 / 候选 / 已证实）
5. **图数上限与正文/补充分配**
6. **受众**：临床 / 生信 / 交叉
7. **必须包含/必须回避的内容**（合作方要求、伦理表述、单位署名等）
8. **篇幅与截止**：决定 L1→L2 的取舍顺序

### 4.2 记录

文件：`02_writing/p2_customization.yaml`

```yaml
customization_id: cust_20260915_160000
timestamp: 2026-09-15T16:00:00+08:00
filled_by: user
complete: true

items:
  - key: research_question
    value: 化合物 X 通过 PI3K/AKT 通路抑制 HCC 增殖
  - key: target_journal
    value: Biomedicine & Pharmacotherapy
  - key: story_type
    value: hypothesis-led
  - key: evidence_boundary
    value: 候选
  - key: figure_limit
    value: 8
  - key: audience
    value: 交叉
  - key: must_include
    value: 伦理声明、WB 原图
  - key: must_avoid
    value: 无
  - key: deadline
    value: 2026-10-01
```

## 5. WP-1~9 九节点

### 5.1 九节点顺序（**不可逆**）

```text
WP-0 素材就绪
   ↓
WP-CORE 逻辑链 P0–P4
   ↓
WP-4 方法 ─┐
WP-5 结果 ─┼─► 四节定稿
WP-6 讨论 ─┤
WP-7 参考 ─┘
   ↓
WP-2 摘要（首句必须是 P1）
   ↓
WP-3 背景（调 research_survey_skill，防幻觉文献）
   ↓
WP-1 标题（最后定稿）
   ↓
WP-8 去 AI 味（初步过滤）
   ↓
WP-9 三格式导出
```

### 5.2 两处反惯例

| 反惯例 | 理由 |
|---|---|
| 摘要在正文之后 | 防"先写摘要再让正文凑数"（NC-6 倒挂） |
| 标题在最后 | 防"标题先定、正文向标题凑"（T1.1 越界） |

### 5.3 各节点判据

#### WP-0 素材就绪

| # | 判据 | 检测 |
|---|---|---|
| 0.1 | P1 接口文件存在 | 文件检查 |
| 0.2 | 至少 1 条 evidence | 计数 |
| 0.3 | 至少 1 张图 | 计数 |
| 0.4 | 参考文献库存在 | 文件检查 |

#### WP-CORE 逻辑链 P0–P4

| 项 | 说明 |
|---|---|
| P0 | 背景问题 |
| P1 | 主发现（唯一，不可多） |
| P2 | 支撑证据 |
| P3 | 局限 |
| P4 | 展望 |

P1 必须唯一，是全文主线。摘要首句、讨论首段首句、标题都基于 P1。

#### WP-1 标题

| # | 判据 | 检测 | 变异用例 |
|---|---|---|---|
| 1.1 | 无升级词（首次/揭示/阐明/驱动/机制/证明/证实） | 词表 | 加"揭示" |
| 1.2 | 无信息词（研究/分析/探索/初探/浅析） | 词表 | 加"的研究" |
| 1.4 | 中文 ≤25 字 / 英文 ≤20 词 | 字符/词数 | 加长 |
| 1.6 | 含研究对象 + 主要发现 | 结构 | 删对象 |

#### WP-2 摘要

| # | 判据 | 检测 | 变异用例 |
|---|---|---|---|
| 2.1 | 首句 == P1 | 比对 | 改首句 |
| 2.2 | 结构四段齐（背景/方法/结果/结论） | 段落扫描 | 删结论段 |
| 2.3 | 字数 ≤目标刊上限 | 字数 | 超 100 字 |
| 2.6 | 末句含边界词 | 词表 | 删边界句 |
| 2.7 | 含 n 与事件数 | 正则 | 删 n |

#### WP-3 背景（★ 与 research skill 的接口）

**接口定义**：

```yaml
research_survey_skill:
  input: topic_keywords · field · year_range · max_results
  output: papers[{DOI,title,authors,journal,year}] + coverage_report
  failure:
    - 未调用 → WP-3 拒入
    - 返回 0 篇 → 判 N/A（第三态），不降级为 AI 生成
```

| # | 判据 | 检测 | 变异用例 |
|---|---|---|---|
| 3.1 | 已调用 skill 并有留痕 | 文件检查 | 删留痕 |
| 3.2 | 引言引用 ∈ skill 输出集合 | 比对 | 加幻觉引用 |
| 3.4 | 含 gap statement（然而/尚未/目前缺乏/仍不清楚） | 词表 | 删 gap |

#### WP-4 方法

| # | 判据 | 阈值 | 变异用例 |
|---|---|---|---|
| 4.1 | 版本/批号 | `v?\d+\.\d+` 或"批号" | 删版本 |
| 4.3 | 统计含单/双侧 + 多重校正 | 词表 | 删双侧 |
| 4.7 | 数据共享登录号 | `GSE\d+\|SRR\d+\|DOI` | 删登录号 |

#### WP-6 讨论

| # | 判据 | 检测 | 变异用例 |

## 6. NC-1~7 叙事约束

### 6.1 七条约束

| 编号 | 检查 | 落点 | 检测 | 变异用例 |
|---|---|---|---|---|
| **NC-1** 悬空问题 | 引言问句 → 讨论有回应 | WP-3 / WP-6 | 句对匹配 | 删回应 |
| **NC-2** 孤证结论 | P1 支撑证据 ≥2 | WP-CORE / WP-6 | 计数 | 删至 1 条 |
| **NC-3** 倒挂 | 讨论首段 = P1 | WP-6.1 | 比对 | 改首段 |
| **NC-4** 平行叙事 | 结果间有递进连接词 | WP-5a | 词表 | 删连接词 |
| **NC-5** 图文脱节 | "如图 X" 后有目的词 | WP-5a/b | 词表 | 删目的词 |
| **NC-6** 摘要双头 | 摘要首句 = P1 | WP-2.1 | 比对 | 改首句 |
| **NC-7** 新发现注入 | 讨论引用 ⊆ 结果引用 | WP-6 | 集合比对 | 加新引用 |

### 6.2 对称守卫

**NC-3 与 NC-6 是同一约束的两次检查**（P1 同时是摘要首句与讨论首段首句）。

两处必须一致，任何一处改 P1，另一处必须同步。不一致 → FAIL。

## 7. 结构序 S1 / S2-a / S2-b / S2-c

### 7.1 四种合法结构

**S1 默认序（BMC 系，无独立 Conclusions）**：

```
题录页 → 结构式摘要 → 关键词 →
引言 → 材料与方法 → 结果 → 讨论 → 声明 → 参考文献
```

**S2-a（含独立 Conclusions，Elsevier/Springer/MDPI 常见）**：

```
题录页 → 结构式摘要 → 关键词 →
引言 → 材料与方法 → 结果 → 讨论 → Conclusions → 声明 → 参考文献
```

**S2-b（结果与讨论合并）**：

```
题录页 → 结构式摘要 → 关键词 →
引言 → 材料与方法 → Results and Discussion → 声明 → 参考文献
```

**S2-c（结论节置于讨论之前）**：

```
题录页 → 结构式摘要 → 关键词 →
引言 → 材料与方法 → 结果 → Conclusions → 讨论 → 声明 → 参考文献
```

### 7.2 结构序判定规则（机器可检）

| 检查 | 判定 | 变异用例 |
|---|---|---|
| 节序串 ∈ {S1, S2-a, S2-b, S2-c} | 自动 | 加非法序 |
| 摘要四段标签齐 + P1 首句 | 自动 | 删结论段 |
| 关键词 3–8 个、分号分隔 | 自动 | 改 2 个 |
| 声明 8 项小标题齐 | 自动 | 删声明项 |
| 图注自明四要素 | 自动 | 删要素 |

### 7.3 目标期刊选择

| 社 | 默认结构序 |
|---|---|
| Elsevier | S2-a |
| Springer | S2-a |
| BMC | S1 |
| Nature 系 | S2-a（方法在参考文献后，特殊） |
| Wiley | S2-a |
| Frontiers | S2-a |
| MDPI | S2-a |

**规则**：投稿前必须核对目标期刊 Guide for Authors。

## 8. 声明块 8 项

### 8.1 八项清单

1. Ethics approval and consent to participate
2. Consent for publication
3. Availability of data and materials
4. Competing interests
5. Funding
6. Authors' contributions（CRediT）
7. Acknowledgements
8. Declaration of generative AI use

### 8.2 位置

正文之后、参考文献之前。

### 8.3 六社差异

| 社 | 特色声明 | 位置 |
|---|---|---|
| Elsevier | CRediT 必填；Declaration of competing interest；Data availability | 正文后 |
| Springer | 致谢、基金、利益冲突放**标题页** | 标题页 |
| BMC | **8 个子标题全列，不适用写 Not applicable** | Declarations |
| Nature 系 | 单独 Data availability + Code availability；生命科学必交 **Reporting Summary** | 参考文献后 |
| Frontiers | Data Availability / Ethics Statement / Author Contributions / Funding / Conflict of Interest / Generative AI / Publisher's Note | 文末 |
| MDPI | Author Contributions / Funding / IRB Statement / Informed Consent / Data Availability / Acknowledgments / Conflicts of Interest | 文末 |

### 8.4 BMC 硬规则

## 9. 证据边界与措辞纪律

### 9.1 证据等级 ↔ 主张上限

| 证据等级 | 达成条件 | 主张上限 | 摘要可写 | 讨论可写 | 图注可写 |
|---|---|---|---|---|---|
| **候选** | 单次 discovery 支持 | L1 | "发现集中相关""提示""候选" | 可提假设与局限，不得谈泛化 | "探索性" |
| **强化** | 内部稳健性/敏感性一致 | L1–L2 | "多种分析下稳健""正交支持" | 可讨论生物学含义，须带"待独立验证" | "探索性" |
| **可转化候选** | 独立数据方向 + 区间满足 T14 | L2 | "方向一致""转化一致性" | 可比较、讨论边界，不得谈临床效用 | "非临床效用验证" |
| **证据** | 功能/机制（L3）或临床效用（L4） | L3 / L4 | 仅针对具体主张 | 严格限定 | 标注实验类型 |

### 9.2 贯穿硬规则

> 图注强度 ≤ 正文强度 ≤ 摘要强度 ≤ 证据上限。

任一处超标 → R5 回退，重算受影响文本与图注。

### 9.3 措辞纪律表

| 禁用 | 替代 |
|---|---|
| 外部验证 | 在独立数据集中**方向一致**；转化一致性 |
| 验证了该标志物 | 该候选**方向得到重复** |
| 诊断标志物 | 与目标状态相关的**候选标志物** |
| 可用于临床诊断 | 判别表现为【待台账】,**尚需前瞻性验证** |
| 机制阐明 / 驱动 / 调控 | **提示**涉及某程序；**计算扰动预测**可能参与 |
| 显著改善临床决策 | 增量指标为【待台账】;决策意义**尚需**验证 |
| 已证实结合 / 有效药物 | **候选优先级排序**;待实验验证的候选化合物 |
| 首次发现 | 在本研究检索范围内未见报道 |
| 结果稳健 / 所有分析均显著 | 在预注册的 5 项敏感性分析中，**M 项方向一致** |
| X 导致 Y | X 与 Y 风险升高相关 |

### 9.4 硬规则

- 探索级结论**必须带限定词**（探索性 / 事后 / 待验证）。
- **润色不得升级 claim**。
- 升级即 R5 回退。

## 14. Title Page 与 Cover Letter

### 14.1 Title Page 必含要素

1. Title：简洁、信息量足、避免缩写和公式
2. Running title：≤40 字符（Wiley）；Frontiers ≤5 词
3. 作者全名：顺序与投稿系统一致
4. 单位：科室/院系、机构、城市、邮编、国家
5. 通讯作者：姓名、完整地址、E-mail、电话；建议附 ORCID
6. 共同第一作者：星号 + "These authors contributed equally to this work"
7. 字数统计：正文字数、摘要字数、图数、表数
8. 盲审期刊：Title Page 单独上传

- 说明创新点
- 符合期刊范围
- 未一稿多投

## 16. 图像完整性红线

### 16.1 允许

- 全图线性亮度/对比度/色彩平衡调整
- 裁剪（不为了删除相关数据）
- 旋转、等比缩放
- 伪彩用于灰度荧光图，须在图注说明

### 16.2 禁止

- 局部增强、遮盖、移动、删除或添加任何特征
- 克隆图章、修复画笔、橡皮擦、内容识别填充
- 过饱和/过度对比度
- 不同凝胶/曝光/实验的条带拼接成"连续膜"而不标注
- 同一图片重复使用（哪怕旋转/镜像）而不声明
- 重复使用对照组图片/泳道于不同实验而不说明
- **生成式 AI 生成或修改任何代表原始实验数据的图像**

### 16.3 必须

- 保留原始未处理文件（含元数据），投稿后至少保存 10 年
- 所有非线性调整（gamma）在图注披露
- 图注或方法中列出图像处理软件

### 16.4 检测

| # | 判据 | 检测 | 变异用例 |
|---|---|---|---|
| I1 | 无局部增强/擦除/移位 | 检测 | 注入局部调整 |
| I2 | 亮度对比度全图统一 | 元数据 | 只调实验组 |
| I3 | 无 AI 生成/修改数据图 | 声明扫描 | 加 AI 生成图 |
| I4 | 保留原始文件 | 目录 | 删原始 |
