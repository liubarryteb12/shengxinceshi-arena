# 第一部分 · 总纲要

## 1. 系统定位

一套**用户驱动 + agent 编排 + 证据可追溯 + 排版可验证**的 SCI 论文生产系统。

用户管方向和取舍，agent 管执行和记录。四部分互相约束、互相反馈、形成闭环。

## 2. 四部分定位

| 部分 | 定位 | 一句话 |
|---|---|---|
| **P1** 生信分析 | 证据生产层 | 从数据到可引用的结构化证据 |
| **P2** SCI 写作 | 稿件生产层 | 从证据到符合目标期刊的稿件 |
| **P3** 文稿自动排版 | 投稿包生产层 | 从稿件到符合期刊要求的投稿包 |
| **P4** 期刊分析 | 策略层 | 前端定方向，后端定投稿 |

## 3. 整体架构

```text
┌──────────────────────────────────────────────────────────────┐
│                    P4-a 题材初判与期刊方向预判                  │
│  产出：期刊方向包（约束 P1/P2/P3）                              │
└──────────────────────────────────────────────────────────────┘
                            ↓ 前馈约束
┌──────────────────────────────────────────────────────────────┐
│  P1 生信分析          P2 SCI 写作          P3 文稿自动排版      │
│  ┌────────┐          ┌────────┐          ┌────────┐          │
│  │ 证据   │ ──────→  │ 稿件   │ ──────→  │ 投稿包 │          │
│  └────────┘          └────────┘          └────────┘          │
│       ↑                    ↑                    ↑             │
│       │                    │                    │             │
│  用户干预点           用户干预点           用户干预点           │
└──────────────────────────────────────────────────────────────┘
                            ↓ 后验反馈
┌──────────────────────────────────────────────────────────────┐
│                  P4-b 成稿质量与投稿定位复审                    │
│  产出：推荐期刊列表 + 投稿顺序 + 反馈路径                       │
└──────────────────────────────────────────────────────────────┘
                            ↓ 反馈（回 P1/P2/P3）
```

## 6. 闭环机制

```text
P4-a 前馈约束 → P1 → P2 → P3 → P4-b 后验复审
                                      ↓
                                    反馈
                                      ↓
                            P1 / P2 / P3 补强
                                      ↓
                                  重新走流程
```

**闭环三条件**：

1. P4-b 必须与 P4-a 对比（实测 vs 预估）。
2. 不匹配必须给出反馈路径。
3. 反馈必须能回到 P1/P2/P3。

# 第二部分 · 总安排

## 7. 建设顺序

### 7.1 分五轮

| 轮次 | 目标 | 交付 |
|---|---|---|
| **第 1 轮** | 立骨架 | P1/P2/P3/P4 目录 + 接口文件定义 + 空规则 |
| **第 2 轮** | 填 P1 | P1 模块化 + 执行引擎 + 复审 + 沉淀 |
| **第 3 轮** | 填 P2 | P2 WP-1~9 + NC-1~7 + 结构序 + 措辞纪律 |
| **第 4 轮** | 填 P3 | P3 排版 + 出图 + 五格式 + 双轨行距 |
| **第 5 轮** | 填 P4 | P4-a 方向包 + P4-b 复审 + 期刊数据库 |
| **第 6 轮** | 消融 | 所有 A 档判据配变异用例 + 先 FAIL 后 PASS |
| **第 7 轮** | 联调 | 跑通一个最小闭环（GSE31210 或同类） |

### 7.2 每轮验收标准

| 轮次 | 验收 |
|---|---|
| 第 1 轮 | 目录树齐全；接口文件字段完整；空规则有登记 |
| 第 2 轮 | P1 最小闭环跑通：一个数据集 + 一个分析 + 生成 manifest |
| 第 3 轮 | P2 最小闭环跑通：用 P1 结果写 Methods 和 Results |
| 第 4 轮 | P3 最小闭环跑通：套模板编译 PDF + 跑排版检查 |
| 第 5 轮 | P4 最小闭环跑通：给定稿件输出推荐期刊 |
| 第 6 轮 | 所有 A 档判据至少 1 个变异用例；抓不到 = 空规 |
| 第 7 轮 | 端到端跑通 P4-a → P1 → P2 → P3 → P4-b |

## 8. 依赖关系

```text
第 1 轮（骨架）
  ├── 第 2 轮（P1）依赖第 1 轮
  ├── 第 3 轮（P2）依赖第 2 轮（P1 接口）
  ├── 第 4 轮（P3）依赖第 3 轮（P2 接口）
  ├── 第 5 轮（P4）依赖第 1 轮（接口定义）
  └── 第 6 轮（消融）依赖第 2–5 轮全部完成
        └── 第 7 轮（联调）依赖第 6 轮
```

**关键路径**：第 1 轮 → 第 2 轮 → 第 3 轮 → 第 4 轮 → 第 6 轮 → 第 7 轮。

**可并行**：第 5 轮（P4）可与第 2–4 轮并行。

# 第九部分 · 建设建议

## 26. 优先建设顺序

**如果只能先做一件事**：先做第 1 轮骨架 + P1 最小闭环。

**理由**：

1. P1 是证据生产层，是 P2/P3/P4 的上游。
2. P1 跑通后，P2 可以用真实证据写稿件。
3. P2 跑通后，P3 可以套真实稿件排版。
4. P3 跑通后，P4-b 可以对真实投稿包复审。
5. P4-a 可以并行建设。

## 27. 风险提示

| 风险 | 缓解 |
|---|---|
| 判据过多，维护成本高 | 按 A/B/C 三档分级；A 档必做，B 档休眠，C 档不立 |
| 消融用例多，测试时间长 | 优先覆盖 A 档；B 档可用合成样本 |
| 接口多，容易不一致 | 唯一真源 + 接口矩阵 + 机器检查 |
| 期刊数据易过期 | 快照 + 时间戳 + 人工确认 |
| 排版参数多，容易遗漏 | 参数卡 + 检查清单 + 变异测试 |
| 叙事定制需求多 | L0/L1/L2 分级；缺需求不写深 |

## 28. 一句话总结

> **P1 产证据，P2 写稿件，P3 排投稿包，P4 定策略。**  
> **P4-a 前馈，P4-b 后验，四部分形成闭环。**  
> **每条规则能构造 FAIL，每个判据能过消融。**  
> **用户管方向，agent 管执行和记录。**
