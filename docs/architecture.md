# shengxinceshi-arena 架构基线

## 数据流

```text
用户想法/数据
    ↓
P4-a 期刊方向包
    ↓
P1 证据包
    ↓
P2 稿件包
    ↓
P3 投稿包
    ↓
P4-b 推荐期刊、投稿顺序与反馈
    ↓
用户决策 / 回到 P1、P2、P3 补强
```

## 阶段边界

- **P4-a**：在分析前做粗筛，只输出方向性约束，不替用户做最终期刊决定。
- **P1**：只生产可追溯证据，不把结果直接写成未经支持的结论。
- **P2**：只读取 P1 接口和 handoff，不直接读取模块脚本作为证据来源。
- **P3**：只改变排版与投稿包组织，不改变数字、证据映射和 claim 强度。
- **P4-b**：读取 P1/P2/P3 的实际产出，与 P4-a 对比，并给出反馈路径。

## 第 1 轮完成边界

本轮只建立可检查的骨架和接口契约，所有实际分析、写作、排版、期刊推荐均保持 `pending`，不制造假结果。
